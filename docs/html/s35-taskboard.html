S3.5自组织与任务板：没人派活，自己认领

模块：taskboard

1. 这个模块解决了什么

没有领导逐个派活——Agent 看共享任务板，自己认领能干的任务。某个 worker 宕机，超时后任务释放，别人接手。

2. 机制

TaskCard(id, title, requiredSkill, status, claimedBy, claimedAt)
   status: PENDING → CLAIMED → DONE
              ↑           ↓
              └── release（超时释放回 PENDING）

3. 关键设计

乐观锁认领：synchronized 块里只有 PENDING 才认领——两个 worker 抢同一任务，只有一个成功。
技能匹配：worker 按 skill() 找 listBySkill() 的 PENDING 任务。
宕机交接：认领超时未完成 → release 回 PENDING → 别人接手。

5.5 核心类详解

TaskBoardDemo（演示入口）

作用：启动任务板演示，展示多 worker 自组织认领任务。

TaskBoard（任务板）

作用：任务队列，管理任务状态。

方法：
方法作用输入输出
submit(TaskCard task)提交任务任务卡片无
claim(String taskId, String workerId)认领任务（乐观锁）任务 ID、worker ID是否认领成功

TaskCard（任务卡片）

作用：任务的数据结构。

字段：id / title / skill / status / assignee

TaskStatus（任务状态枚举）

作用：任务状态。

枚举值：PENDING / RUNNING / DONE

Worker（工人接口）

作用：定义工人的接口。

AutonomousCoordinator（自组织协调器）

作用：协调多个 worker 认领任务。

🚀 初学者快速上手

前置知识：理解"乐观锁"（多人抢同一资源，只有一个成功）。
核心概念一句话：没人派活，Agent 自己看任务板认领，宕机了别人接手。
跑起来看：TaskBoardDemo 里 3 个 worker 各认领匹配技能的任务。

4. 运行命令

mvn -q -pl s35-taskboard exec:java "-Dexec.mainClass=com.example.agentlab.taskboard.TaskBoardDemo"
核心：自组织——无领导派活，worker 自主协作、容错。
