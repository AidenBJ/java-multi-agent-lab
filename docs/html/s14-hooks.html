S1.4Hooks 与可观测性：记录每一步轨迹

模块：hooks

1. 这个模块解决了什么

Agent 跑起来做了什么？看不到就是黑盒。Hooks（观察者模式）在循环每步插点，记录轨迹——用户能看到 LLM 调了什么工具、返回了什么。

2. 核心知识点

Observer 模式：AgentObserver 接口，在循环开始/工具调用/工具返回/结束时回调。
TraceObserver：实现观察者，把每步事件收集成轨迹报告。
可观测性：不是功能，是"看得见"——调试、审计、教学都靠它。

3. 实现步骤

步骤 1：定义 AgentObserver 接口（onStart/onToolCall/onToolResult/onEnd）。
步骤 2：TraceObserver 实现——把事件存成 List。
步骤 3：在 AgentLoop 每步调用 observer 回调。

4. 逻辑流程

AgentLoop 每步：
  onStart(prompt)
    ↓
  LLM → 工具调用
  onToolCall(name, args)
    ↓
  工具执行
  onToolResult(name, result)
    ↓
  onEnd(reply)

5. 关键代码

public interface AgentObserver {
    default void onStart(String prompt) {}
    default void onToolCall(String name, String args) {}
    default void onToolResult(String name, String result) {}
    default void onEnd(String reply) {}
}

5.5 核心类详解

Hook（钩子接口）

作用：定义钩子接口，在关键节点插入回调。

Hooks（钩子管理器）

作用：管理所有钩子，在关键节点触发。

方法：
方法作用
onStart(input)开始时触发
onToolCall(toolName, args)调用工具时触发
onEnd(output)结束时触发

AgentRunner（带钩子的 Agent 执行器）

作用：在 Agent 执行过程中，在关键节点触发钩子。

🚀 初学者快速上手

前置知识：理解观察者模式（设计模式里常见的那种）。
核心概念一句话：在 Agent Loop 每步插一个"记录员"，把发生的事全记下来。
价值：这是调试 Agent 的眼睛——后面所有阶段出问题都靠 hooks 看发生了什么。
