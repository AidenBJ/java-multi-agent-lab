S3.3通信协议与 Handoff：固定格式的请求-回复

模块：protocol

1. 这个模块解决了什么

多 Agent 协作靠自由文本传话，格式随 LLM 发挥而变。协议：固定格式的信封，错误可识别，转交可追溯。

2. 信封结构

Envelope(version, messageId, from, to, type, payload)
   type: REQUEST / RESULT / ERROR / HANDOFF
   payload: 按 type 解析为对应 record

3. 标准错误码

E_INVALID_MESSAGE — 消息格式不合法
E_UNSUPPORTED_VERSION — 协议版本不兼容
E_UNKNOWN_RECIPIENT — 目标不存在
E_PAYLOAD_MISMATCH — payload 与类型不匹配

4. Handoff 语义

writer 收到代码任务 → HANDOFF{forwardTo:"coder", reason:"..."}
   ↓
总线路由到 coder → coder 接手

5. 实测发现

Jackson 对畸形 JSON 宽容不抛异常——协议层自加 payload 结构校验（必须以 { 开头）兜底。

5.5 核心类详解

ProtocolDemo（演示入口）

作用：启动协议演示，展示 writer 和 coder 按协议交互，含 handoff 和错误拒绝。

AgentProtocol（协议路由器）

作用：路由信封到对应的接收者。

Envelope（消息信封）

作用：信封的数据结构。

字段：
字段作用
version协议版本
messageId消息 ID
from发送者
to接收者
type消息类型
payload载荷（JSON）

MessageType（消息类型枚举）

作用：消息类型。

枚举值：REQUEST / RESULT / HANDOFF / ERROR

ProtocolCodec（编解码器）

作用：载荷的 JSON 编解码。

🚀 初学者快速上手

前置知识：理解 JSON 和"结构化消息"。
核心概念一句话：Agent 间传话要固定格式，错误可识别，转交可追溯。
跑起来看：ProtocolDemo 里文章任务 writer 自处理，代码任务 handoff 给 coder，未知接收方报错。
