S2.4上下文压缩：四层管线

模块：context-compact

1. 这个模块解决了什么

对话越跑越长，token 超限就报错。上下文压缩：四层管线从粗到细压缩历史，让上下文不超限。

2. 四层管线（顺序固定）

L3 大结果落盘：工具返回的大结果（文件内容等）先落盘，上下文里只留引用。
L1 裁中间：留头 3 条 + 尾 N 条，中间裁掉。tool_use/tool_result 配对保护。
L2 旧结果占位：旧工具结果替换成"结果见引用"占位符。
L4 LLM 摘要：前三层不够，LLM 全量摘要历史（阈值触发）。

3. 逻辑流程

messages 累积
   ↓
L3（大结果落盘）→ L1（裁中间）→ L2（旧结果占位）→ L4（LLM 摘要，按需）
   ↓
压缩后的 messages 继续跑

4. 实测数据

实测：84 条 → 53 条，节省 ≈36k token。

5. 关键设计

tool_use/tool_result 配对保护：切口压在 ToolResult 上时 headEnd 自动推进，不拆配对。
token 估算 = 总字符数/4（教学简化）。

5.5 核心类详解

Compactor（压缩器）

作用：对话太长时，自动压缩历史消息。

方法：
方法作用输入输出
compact(List<ChatMessage> messages)压缩消息消息列表压缩后的摘要

Summarizer（摘要生成器）

作用：用 LLM 生成对话摘要，保留关键信息。

MessageWindow（消息窗口）

作用：管理消息窗口，超出大小触发压缩。

🚀 初学者快速上手

前置知识：理解 token 限制（对话太长会超限报错）。
核心概念一句话：对话太长了，从粗到细压缩历史，让上下文不超限。
实测数据：跑 CompactDemo 看 84 条压成 53 条，省 36k token。

6. 运行命令

mvn -q -pl s24-context-compact exec:java "-Dexec.mainClass=com.example.agentlab.contextcompact.CompactDemo"
顺序固定：budget 必须最先跑——micro 会把旧结果替换成占位符，顺序错了就丢信息。
