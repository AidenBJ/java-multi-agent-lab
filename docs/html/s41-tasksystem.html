S4.1持久化任务系统：任务图 DAG + 落盘续跑

模块：tasksystem

1. 这个模块解决了什么

把"目标"从单次对话里拿出来——任务图落盘、依赖排序、状态流转。崩溃后可续跑。

2. 机制

TaskRecord(id, title, blockedBy[], status, result)
   status: PENDING → RUNNING → DONE / FAILED
   blockedBy: 依赖的任务 ID，全部 DONE 后本任务才 ready

3. 关键设计

DAG 就绪判定：readyTasks()——PENDING 且 blockedBy 全部 DONE。
磁盘持久化：TaskStore 存成 JSON 文件，重启 load() 加载续跑。
执行循环：反复找 ready → 执行 → 标记 → 落盘。

5.5 核心类详解

TaskSystemDemo（演示入口）

作用：启动任务系统演示，展示 DAG 执行 + 持久化 + 重启续跑。

TaskGraph（任务图）

作用：管理任务的依赖关系。

TaskRecord（任务记录）

作用：任务的数据结构。

字段：id / title / dependsOn / status / result

TaskStatus（任务状态枚举）

作用：任务状态。

枚举值：PENDING / READY / RUNNING / DONE / FAILED

TaskRunner（任务执行器）

作用：自动调度就绪任务执行。

TaskStore（任务存储）

作用：把任务状态持久化到磁盘。

🚀 初学者快速上手

前置知识：理解 DAG（有向无环图）。
核心概念一句话：任务有依赖，全部做完依赖才能开始，落盘持久化。
跑起来看：TaskSystemDemo 里 A→B→C 依赖链执行，落盘，重启加载。

mvn -q -pl s41-tasksystem exec:java "-Dexec.mainClass=com.example.agentlab.tasksystem.TaskSystemDemo"
