S3.6团队总线与异步邮箱：解耦与可扩展

模块：bus

1. 这个模块解决了什么

多 Agent 互相直接调用，耦合死——加一个 Agent 要改所有调用方。消息总线：发布者不认识订阅者，靠 topic 解耦。

2. 机制

Message(id, topic, from, to, payload)
   ↓ publish
MessageBus
   ├─ to==null → 广播给 topic 所有订阅者
   └─ to!=null → 定向投递给该名字的订阅者

3. 关键设计

开闭原则：新增订阅者 = subscribe() 一行，不改任何现有代码。
邮箱：Mailbox 用 BlockingQueue 存收件，异步收消息。

5.5 核心类详解

BusDemo（演示入口）

作用：启动消息总线演示，展示订阅/广播/定向三种模式。

MessageBus（消息总线）

作用：消息路由中心，管理订阅和发布。

方法：
方法作用输入输出
subscribe(String topic, String workerId, Consumer handler)订阅 topictopic、worker ID、处理函数无
publish(Message msg)发布消息消息对象无

Message（消息对象）

作用：消息的数据结构。

字段：id / topic / from / to / payload

Mailbox（邮箱）

作用：worker 的收件箱，存收到的消息。

🚀 初学者快速上手

前置知识：理解"发布-订阅"模式（设计模式常见）。
核心概念一句话：发布者不认识订阅者，靠 topic 解耦，加人不改代码。
跑起来看：BusDemo 广播 coding 任务，定向 writer 任务，邮箱计数验证。

4. 运行命令

mvn -q -pl s36-bus exec:java "-Dexec.mainClass=com.example.agentlab.bus.BusDemo"
