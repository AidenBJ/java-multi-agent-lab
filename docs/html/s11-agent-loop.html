S1.1显式 Agent Loop：手写循环 vs 状态图

模块：agent-loop

1. 这个模块解决了什么

对话不只是一问一答——LLM 可能要求调用工具，工具结果要回填，再让 LLM 继续。这个"messages → LLM → 工具调用 → 执行 → 回填 → 循环"就是 Agent Loop。先手写一遍理解原理，再用 langgraph4j 状态图对比。

2. 核心知识点

Agent Loop 本质：一个 while 循环，LLM 输出 tool_use 就执行工具、回填 tool_result，直到 LLM 不再要工具才返回文本。
消息配对：tool_use 和 tool_result 必须一一配对（Messages API 语义）。
langgraph4j 状态图：StateGraph 把节点（node）和边（edge）组装成图，框架帮你跑循环。
AgentObserver：在循环每步插观察者，记录轨迹（为后面 hooks 铺垫）。

3. 实现步骤

步骤 1：手写 AgentLoop——while 循环里调 LLM，检查是否有 toolUse，有就执行回填。
步骤 2：实现 FakeChatModel——离线桩，预设回复序列，不调真实 LLM。
步骤 3：langgraph4j 版——SimpleState + ResponderNode + GreeterNode 组装图。

4. 逻辑流程

用户输入
   ↓
┌→ LLM.chat(messages)
│     ↓
│  有 tool_use？──是→ 执行工具 → 回填 tool_result → 回循环
│     ↓否
└─ 返回文本回复

5. 关键代码（langgraph4j 图）

var graph = new StateGraph<>(SimpleState.SCHEMA, SimpleState::new)
    .addNode("greeter", node_async(this::greeterNode))
    .addNode("responder", node_async(this::responderNode))
    .addEdge(START, "greeter")
    .addEdge("greeter", "responder")
    .addEdge("responder", END)
    .compile();

5.5 核心类详解

AgentLoop（主循环）

作用：手写 Agent 循环，控制消息流转。

核心循环：消息 → LLM → 有工具调用？→ 执行 → 回填 → 循环

ChatModel（LLM 调用）

作用：调用 LLM，发送消息获取回复。

ToolExecutor（工具执行器）

作用：执行工具调用，把结果回填给 LLM。

🚀 初学者快速上手

前置知识：跑完 S0.2，理解"对话"和"工具调用"的区别。
核心概念一句话：Agent Loop 就是"LLM 说要调工具 → 你执行 → 把结果给它 → 它继续想"的循环。
离线可跑：FakeChatModel 是桩，不调真实 LLM，直接跑 SimpleGraphApp 看状态图怎么流转。
