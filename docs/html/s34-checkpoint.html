S3.4检查点：落盘→崩溃恢复→时间旅行

模块：checkpoint

1. 这个模块解决了什么

任务跑到一半崩溃了？检查点：每步落盘全状态，重启后从最新检查点恢复，从下一步继续，不重跑。

2. 机制

Checkpoint(step, node, state, timestamp)
   ↑ 每步执行后落盘
CheckpointStore
   ├─ MemoryCheckpointStore（进程内演示）
   └─ FileCheckpointStore（JSON 文件，真正的关机恢复）

3. 关键设计

step 序号即恢复指针：跑完 step i 后落 step=i+1；resume 从 steps.get(step) 继续。
时间旅行：listHistory() 返回全部历史快照，可回看任意中间时刻状态。

4. 逻辑流程

run：落 step=0 → 跑 step1 → 落 step1 → 跑 step2 → 落 step2 ...
   ↓ 崩溃
resume：loadLatest → 拿到 step=2 → 从 steps.get(2) 继续

5.5 核心类详解

CheckpointDemo（演示入口）

作用：启动检查点演示，展示崩溃恢复和时间旅行。

CheckpointedRunner（带检查点的执行器）

作用：执行步骤序列，每步落盘检查点。

方法：
方法作用输入输出
run(String threadId, List<Step> steps, Map state)执行步骤序列线程 ID、步骤列表、初始状态最终状态
resume(String threadId, List<Step> steps)从检查点恢复线程 ID、步骤列表恢复后的最终状态

Checkpoint（检查点对象）

作用：检查点的数据结构。

字段：threadId / step / node / state / timestamp

CheckpointStore（检查点存储接口）

作用：定义检查点存储的接口。

Step（步骤接口）

作用：定义步骤的接口。

🚀 初学者快速上手

前置知识：理解"持久化"（存到磁盘）。
核心概念一句话：每步落盘全状态，崩溃了重启从上次继续，不重跑。
跑起来看：CheckpointDemo 跑到一半"崩溃"，恢复后继续，时间旅行看每步状态。

5. 运行命令

mvn -q -pl s34-checkpoint exec:java "-Dexec.mainClass=com.example.agentlab.checkpoint.CheckpointDemo"
