S1.3权限与人工确认：未确认绝不执行

模块：permission

1. 这个模块解决了什么

LLM 想执行危险操作（删文件、发请求）怎么办？不能直接执行——必须先问人。审批门：执行前先卡在"确认"节点，人说 yes 才继续，说 no 就拒绝。

2. 核心知识点

状态机：langgraph4j 状态图——执行前先过审批节点，条件边根据"确认/拒绝"路由。
条件边：addConditionalEdges 根据状态里的 decision 路由到 ExecuteNode 或 DeniedNode。
人机协作：人是循环的一部分——停下来等输入，不是全自动。

3. 实现步骤

步骤 1：ApprovalState——状态含 action、decision。
步骤 2：GuardNode——显示要执行的动作，等用户输入 y/n。
步骤 3：DecisionNode——把用户输入写进 decision。
步骤 4：条件边——decision==yes → ExecuteNode；no → DeniedNode。

4. 逻辑流程

START → GuardNode（问：要执行 X，y/n?）
   ↓
DecisionNode（记 decision）
   ↓
┌条件边──────────┐
yes → ExecuteNode（执行）→ END
no  → DeniedNode（拒绝）→ END

5. 关键代码

g.addConditionalEdges("decision",
    edge_async(state -> state.decision()),
    Map.of("yes", "execute", "no", "denied"));

5.5 核心类详解

GuardNode（权限判断节点）

作用：判断操作是否危险，决定是否需要人工确认。

方法：
方法作用输入输出
check(String operation)检查操作是否安全操作描述是否需要确认

ApprovalGate（确认门）

作用：等待人工输入 yes/no，确认后才执行。

Executor（最终执行器）

作用：确认通过后，真正执行操作。

🚀 初学者快速上手

前置知识：理解状态图（S1.1）。
核心概念一句话：危险操作前先卡在"问人"节点，人说 yes 才继续。
跑起来看：执行 ApprovalGraphApp，控制台会问"要执行这个操作吗 y/n"，输 y 看通过，输 n 看拒绝。

mvn -q -pl s13-permission exec:java "-Dexec.mainClass=com.example.agentlab.permission.ApprovalGraphApp"
