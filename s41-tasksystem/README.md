# S4.1 任务系统

> Phase 4 · 工程化

## 这个模块在干什么？

任务图 DAG：依赖关系、自动调度、持久化。

核心原理：任务有依赖关系（A 做完才能做 B），系统自动找就绪的任务执行，状态存到磁盘，进程挂了重启能从上次的地方继续。

## 学习目标

理解：DAG 任务调度、依赖管理、持久化续跑

## 核心类详解

### TaskSystemDemo（演示入口）

**作用**：启动任务系统演示，展示 DAG 执行 + 持久化 + 重启续跑。

**方法**：

| 方法 | 作用 | 输入 | 输出 |
|------|------|------|------|
| `main(String[] args)` | 主入口，构建任务图，执行，重启续跑 | 命令行参数 | 无 |

**关键流程**：

1. 创建 `TaskStore` — 持久化存储
2. 创建 `TaskGraph` — 任务图
3. 添加任务 A→B→C（依赖链）
4. 创建 `TaskRunner` — 执行器
5. `runner.run(graph)` — 执行
6. 模拟重启：从磁盘加载，续跑

### TaskGraph（任务图）

**作用**：管理任务的依赖关系。

**方法**：

| 方法 | 作用 | 输入 | 输出 |
|------|------|------|------|
| `add(TaskRecord task)` | 添加任务 | 任务记录 | 无 |
| `all()` | 列出所有任务 | 无 | 任务列表 |
| `visualize()` | 可视化任务图 | 无 | 可视化字符串 |

### TaskRecord（任务记录）

**作用**：任务的数据结构。

**字段**：

| 字段 | 作用 |
|------|------|
| `id` | 任务 ID |
| `title` | 任务标题 |
| `dependsOn` | 依赖的任务 ID 列表 |
| `status` | 任务状态 |
| `result` | 执行结果 |

**方法**：

| 方法 | 作用 | 输入 | 输出 |
|------|------|------|------|
| `of(String id, String title, List<String> dependsOn)` | 创建任务 | ID、标题、依赖 | TaskRecord 实例 |

### TaskStatus（任务状态枚举）

**作用**：任务状态。

**枚举值**：

| 值 | 含义 |
|------|------|
| `PENDING` | 待执行 |
| `READY` | 就绪（依赖已完成） |
| `RUNNING` | 执行中 |
| `DONE` | 已完成 |
| `FAILED` | 失败 |

### TaskRunner（任务执行器）

**作用**：自动调度就绪任务执行。

**方法**：

| 方法 | 作用 | 输入 | 输出 |
|------|------|------|------|
| `run(TaskGraph graph)` | 执行任务图 | 任务图 | 无 |

**核心流程**：

1. 找所有 READY 的任务
2. 执行任务
3. 任务完成后更新依赖
4. 回到第 1 步，直到所有任务完成

### TaskStore（任务存储）

**作用**：把任务状态持久化到磁盘。

**方法**：

| 方法 | 作用 | 输入 | 输出 |
|------|------|------|------|
| `save(TaskGraph graph)` | 保存任务图 | 任务图 | 无 |
| `load()` | 从磁盘加载 | 无 | 任务图 |

## 执行流程

```
任务依赖：A → B → C

执行：
    A (PENDING → READY) → 执行 → DONE
    B (依赖 A，A 完成 → READY) → 执行 → DONE
    C (依赖 B，B 完成 → READY) → 执行 → DONE

持久化：
    每完成一个任务就存到磁盘
    进程挂了重启，从磁盘加载，继续执行没完成的任务
```

## 在 Web Console 中体验

```bash
mvn -pl web-console spring-boot:run
```

打开 http://localhost:8080，左侧选择 **S4.1 任务系统**，输入任意任务，底部日志面板查看完整流程。
