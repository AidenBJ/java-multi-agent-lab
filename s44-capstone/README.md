# S4.4 综合项目

> Phase 4 · 工程化

## 这个模块在干什么？

端到端流水线：把前面所有模块串起来。

核心原理：用户给一个大目标 → 规划拆解成任务 → 多 worker 按技能认领执行 → 结果聚合 → 落盘。把 S2.1 规划 / S3.5 任务板 / S3.1 主管 / S4.1 任务图 的思想组装成一条完整链路。

## 学习目标

理解：完整多 Agent 系统架构、端到端流水线

## 核心类详解

### CapstonePipeline（流水线）

**作用**：端到端流水线，把所有阶段串起来。

**方法**：

| 方法 | 作用 | 输入 | 输出 |
|------|------|------|------|
| `run(String goal, List<Worker> workers)` | 执行流水线 | 目标、worker 列表 | 最终报告 |
| `main(String[] args)` | 主入口，演示流水线 | 命令行参数 | 无 |

**核心流程**：

1. 规划拆解：把大目标拆成 (任务, 技能) 列表
2. 多 worker 按技能认领执行
3. 聚合结果成最终报告

### Worker（工人接口）

**作用**：定义工人的接口。

**方法**：

| 方法 | 作用 | 输入 | 输出 |
|------|------|------|------|
| `skill()` | 返回技能 | 无 | 技能名 |
| `work(String task)` | 执行任务 | 任务描述 | 执行结果 |

## 执行流程

```
用户目标："行业调研"
    ↓
规划拆解：
    - 调研市场规模 (analysis)
    - 写分析报告 (writing)
    ↓
多 worker 按技能认领：
    分析师 (analysis) → 执行"调研市场规模"
    写手 (writing) → 执行"写分析报告"
    ↓
聚合结果：
    《行业调研》最终报告:
      - [analysis] 分析师完成: 调研市场规模
      - [writing] 写手完成: 写分析报告
```

## 在 Web Console 中体验

```bash
mvn -pl web-console spring-boot:run
```

打开 http://localhost:8080，左侧选择 **S4.4 综合项目**，输入一个完整任务，底部日志面板查看完整流程。
